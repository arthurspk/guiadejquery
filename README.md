## :dart: O guia para alavancar a sua carreira

> jQuery nasceu em 2006 para resolver um problema que hoje quase não existe mais — a inconsistência entre navegadores — e por isso é, ao mesmo tempo, uma das bibliotecas mais usadas da história da web e uma tecnologia em claro declínio para projetos novos. Nenhum framework moderno (React, Vue, Angular) depende dela, e a maioria das vagas júnior de 2026 não pede jQuery como requisito principal. Mas ela continua rodando por trás de uma fatia enorme da web — WordPress a inclui por padrão, sistemas legados de empresas grandes foram construídos sobre ela e ainda recebem manutenção, e a própria biblioteca segue viva: a versão 4.0 foi lançada em janeiro de 2026, no aniversário de 20 anos do projeto. Este guia existe para quem precisa manter, dar suporte ou entender código jQuery hoje — seja em uma vaga de manutenção, em um projeto legado ou em um site WordPress — sem prometer que é o próximo passo natural de quem está começando do zero em front-end. Os recursos em português e gratuitos vêm primeiro em cada seção, e todo link foi verificado.

## 🗺️ Roadmap

jQuery não tem um roadmap.sh oficial como HTML, CSS ou JavaScript — é uma biblioteca, não uma trilha de carreira. O que existe é o histórico e o presente reais da tecnologia, que valem mais que qualquer roadmap fictício:

- [jQuery 4.0.0 — anúncio oficial de lançamento](https://blog.jquery.com/2026/01/17/jquery-4-0-0/) — A versão mais nova da biblioteca, lançada em janeiro de 2026 no aniversário de 20 anos do projeto: módulos ES, remoção de APIs antigas (`jQuery.isArray`, `jQuery.parseJSON` etc.), suporte a Trusted Types e fim do suporte a IE10 e anteriores.
- [Upgrading jQuery: working towards a healthy web](https://blog.jquery.com/2024/04/17/upgrading-jquery-working-towards-a-healthy-web/) — Post oficial explicando por que a equipe está removendo APIs antigas e como isso deixa a web mais segura e rápida.
- [W3Techs — Usage statistics of jQuery](https://w3techs.com/technologies/details/js-jquery) — Estatística real e atualizada: jQuery é usado por cerca de 66% de todos os sites (a maioria por causa do WordPress e de sistemas legados), mas é raro em stacks de projetos novos.
- [Stack Overflow Developer Survey 2025](https://survey.stackoverflow.co/2025/) — Pesquisa anual com a comunidade global; jQuery aparece cada vez mais associado a manutenção, e cada vez menos a projetos greenfield.
- [roadmap.sh — Frontend Roadmap](https://roadmap.sh/frontend) — Para contexto: o caminho de front-end recomendado hoje não passa mais por jQuery — vale entender onde ele ficava antes de HTML/CSS/JS puro dominarem a trilha.

**Trilha resumida** (siga na ordem; cada etapa tem recursos nas seções abaixo):

1. **Pré-requisito** — HTML, CSS e, principalmente, JavaScript puro (variáveis, funções, DOM, eventos). jQuery é uma biblioteca *de* JavaScript, não um substituto para aprendê-lo. Veja o [Guia de JavaScript do Guia Dev Brasil](https://github.com/arthurspk/guiadejavascript) se ainda não tiver essa base.
2. **Contexto histórico** — entenda por que jQuery foi criado (unificar APIs de DOM que eram diferentes em cada navegador em 2006) e por que hoje isso não é mais necessário (os navegadores convergiram e o próprio JavaScript ganhou `querySelector`, `fetch`, `classList` etc.).
3. **Seletores e manipulação do DOM** — a sintaxe `$()`, seleção por CSS, `.html()`, `.text()`, `.attr()`, `.addClass()`/`.removeClass()`, encadeamento de métodos (chaining).
4. **Eventos** — `.on()`, `.click()`, `.submit()`, delegação de eventos para elementos criados dinamicamente.
5. **Efeitos e animações** — `.fadeIn()`/`.fadeOut()`, `.slideToggle()`, `.animate()`.
6. **Ajax** — `$.ajax()`, `$.get()`, `$.post()`, `.done()`/`.fail()`, e como isso se compara ao `fetch()` nativo.
7. **Plugins** — como instalar e usar plugins de terceiros (DataTables, Select2 e outros) — é onde jQuery ainda aparece com mais frequência em vagas reais, geralmente em painéis administrativos.
8. **jQuery 4.0 e o presente** — o que mudou na versão mais recente, como usar o `jQuery Migrate` para atualizar projetos antigos sem quebrar tudo de uma vez.
9. **Saber quando não usar jQuery** — em projetos novos hoje, prefira JavaScript puro ou um framework. Use jQuery para manter, dar suporte ou trabalhar em cima de código legado, WordPress ou protótipos muito rápidos.

**Por onde começar:**

1. **Confirme sua base em JavaScript puro** — sem isso, jQuery vira "decoreba" de métodos sem entender o que está por trás.
2. **Leia a introdução oficial** no [jQuery Learning Center](https://learn.jquery.com/) — é o material mais confiável e ainda mantido sobre a biblioteca.
3. **Rode seu primeiro exemplo** direto no navegador, sem instalar nada (veja o trecho de código abaixo).
4. **Siga um curso completo** — em português, o [Curso completo — jQuery para iniciantes (Thiago Sales)](https://www.youtube.com/watch?v=Nqw-_EYCwnk); em inglês, o [jQuery Crash Course (Traversy Media)](https://www.youtube.com/watch?v=3nrLc_JOF7k).
5. **Pratique manipulando o DOM** em um projetinho pequeno: uma lista de tarefas, um formulário com validação, um acordeão.
6. **Aprenda um plugin popular** usado em produção, como o [DataTables](https://datatables.net/) ou o [Select2](https://select2.org/) — é o cenário mais comum de quem usa jQuery em 2026.
7. **Entenda a migração** — veja o que mudou no [jQuery 4.0](https://blog.jquery.com/2026/01/17/jquery-4-0-0/) e pratique substituir métodos jQuery por JavaScript puro com o [You Might Not Need jQuery](https://youmightnotneedjquery.com/).

Seu primeiro exemplo em 30 segundos, sem instalar nada:

```html
<!-- index.html -->
<!DOCTYPE html>
<html lang="pt-BR">
<head>
  <meta charset="UTF-8">
  <title>Olá, jQuery</title>
</head>
<body>
  <button id="botao">Clique aqui</button>
  <p id="saudacao"></p>

  <!-- CDN oficial do jQuery -->
  <script src="https://code.jquery.com/jquery-4.0.0.min.js"></script>
  <script>
    $(document).ready(function () {
      $("#botao").on("click", function () {
        $("#saudacao").text("Olá, Guia Dev Brasil!").fadeIn();
      });
    });
  </script>
</body>
</html>
```

Salve como `index.html` e abra no navegador — não precisa de Node, build ou instalação.

## 🛠️ Ferramentas

> Plugins usados em produção

- [DataTables](https://datatables.net/) — O plugin de tabelas mais usado sobre jQuery: paginação, busca e ordenação prontas. É onde jQuery mais aparece em sistemas reais hoje.
- [Select2](https://select2.org/) — Substitui `<select>` nativos por campos de busca com autocomplete; muito comum em painéis administrativos.
- [jQuery Migrate](https://github.com/jquery/jquery-migrate) — Plugin oficial que avisa (e corrige em tempo de execução) o uso de APIs removidas em versões novas do jQuery — essencial para atualizar projetos antigos com segurança.

## 🔁 Migrando de jQuery para JavaScript moderno

Em 2026, a tarefa mais comum envolvendo jQuery não é começar um projeto novo com ele — é tirá-lo de um projeto antigo ou mantê-lo funcionando com segurança. Estes recursos ajudam nos dois casos:

- [You Might Not Need jQuery](https://youmightnotneedjquery.com/) — Site de referência que mostra, lado a lado, o código jQuery e o equivalente em JavaScript puro para cada tarefa comum (seletores, eventos, Ajax, animações).
- [You-Dont-Need-jQuery (GitHub)](https://github.com/camsong/You-Dont-Need-jQuery) — Lista extensa e comentada com os mesmos exemplos, organizada por categoria, com suporte de navegador para cada alternativa nativa.
- [PlainJS](https://plainjs.com/) — Referência de JavaScript puro organizada como se fosse a documentação do jQuery — facilita a transição por comparação direta.
- [Porque se criou o jQuery e hoje praticamente não se usa mais? (Ayrton Teshima — Programador a Bordo)](https://www.youtube.com/watch?v=n19eI_7XMAI) — Explicação direta, em português, do contexto histórico e por que ele perdeu espaço.
- [jQuery a biblioteca imortal do JavaScript? (JovemScript)](https://www.youtube.com/watch?v=l8JT7S0ZSzE) — Discussão sobre por que o jQuery continua presente mesmo décadas depois, e onde isso ainda faz sentido.
- [jQuery to Vanilla JS (Sprint Codes — James Moro)](https://www.youtube.com/watch?v=9rFkiduUKSg) — Comparação prática de trechos de código jQuery reescritos em JavaScript puro.
- [Requisição AJAX com JavaScript puro — sem jQuery (Sprint Codes — James Moro)](https://www.youtube.com/watch?v=-84regrj_B0) — Mostra como substituir `$.ajax()` por `fetch()` na prática.

## 🤖 IA na prática

A maior parte do trabalho real com jQuery hoje é ler, entender e atualizar código que outra pessoa escreveu anos atrás — exatamente o tipo de tarefa em que um assistente de IA ajuda mais.

**Para aprender**
- Cole um trecho de código jQuery legado e peça: *"explique o que este código faz, linha por linha, e reescreva em JavaScript puro"*. É uma forma rápida de aprender tanto jQuery quanto sua alternativa nativa ao mesmo tempo.
- Peça para a IA comparar um método jQuery com o equivalente nativo (ex.: `$.ajax()` vs `fetch()`, `.on()` vs `addEventListener()`) com exemplos executáveis — depois teste no [JSFiddle](https://jsfiddle.net/).
- Peça exercícios com gabarito sobre seletores e manipulação de DOM em jQuery para fixar a sintaxe antes de ler código de produção.

**Para trabalhar**
- Use [GitHub Copilot](https://docs.github.com/pt/copilot), [Cursor](https://cursor.com/), [Claude Code](https://code.claude.com/docs/en/overview) ou [Gemini CLI](https://github.com/google-gemini/gemini-cli) para: entender um arquivo jQuery legado sem documentação, identificar chamadas de métodos removidos no [jQuery 4.0](https://blog.jquery.com/2026/01/17/jquery-4-0-0/), e planejar a migração de uma tela por vez para JavaScript puro ou um framework.
- Cole os avisos do console gerados pelo [jQuery Migrate](https://github.com/jquery/jquery-migrate) (ele avisa exatamente quais chamadas antigas seu código usa) e peça à IA para corrigir cada um deles, um de cada vez.
- Peça para a IA gerar testes antes de mexer em código jQuery sem cobertura — é comum código legado não ter nenhum teste, e isso reduz o risco de quebrar algo em produção.
- Use o [Chrome DevTools](https://developer.chrome.com/docs/devtools/javascript) junto com a IA: cole o erro exato do console e peça a causa mais provável antes de aceitar qualquer sugestão.

**Limites e boas práticas**
- A IA tende a "modernizar" código jQuery reescrevendo tudo de uma vez — isso é arriscado em sistemas legados sem testes. Peça migrações incrementais, uma função por vez, e rode a aplicação depois de cada mudança.
- Ela pode sugerir métodos jQuery que já foram removidos em versões recentes (como os listados no anúncio da 4.0) por terem sido comuns em códigos antigos usados no treinamento. Confirme sempre na [documentação oficial](https://api.jquery.com/).
- Não cole código de sistemas internos da empresa, credenciais ou dados de clientes em ferramentas de IA sem verificar a política do seu empregador — muito código jQuery legado convive com integrações sensíveis (formulários, pagamentos, autenticação antiga).
- Entenda o que está sendo trocado antes de aceitar: uma sugestão que "funciona" nem sempre preserva o comportamento exato que o sistema legado dependia (ex.: ordem de eventos, timing de animações).
